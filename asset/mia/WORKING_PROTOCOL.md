# Mia 제작 기준 — 재개 시 먼저 읽기

> 목적은 원화의 인상을 여러 시점에서 유지하면서 이후 교체·표정·애니메이션이 가능한 모델을 만드는 것이다. 현재 산출물은 미승인 연구본이며, 원화와 다른 얼굴·체형을 기술 검증으로 통과시킬 수 없다.

## 기준 원화와 작업 단위

| 대상 | 판단에 사용할 기준 | 적용 범위 |
|---|---|---|
| 얼굴 정체성 | 재확인 얼굴 portrait + 확정 16표정 시트 | 눈매·홍채·코·입·턱·광대·볼. 표정 시트는 미묘한 yaw/pitch/roll의 기준이기도 함 |
| 두상·헤어 | v22 마스터의 정면·측면·후면·사선 + portrait/표정의 근접뷰 | 두개골과 헤어 외피를 구분. 가려진 두개골을 머리카락 윤곽으로 측정하지 않음 |
| 바디 | 선택 정면·종아리 수정 + v06 체형 4뷰와 visibility guide | 가슴의 위치/볼륨/돌출/하부 연결, 골반·허벅지 폭, 허리·복부·목·어깨 곡면. 생성 후보의 승인 상태는 별도 |
| 의상·소품 | v22 착의 4뷰·디테일 패널 | 승인된 본체에 독립 파트로 맞춤. 옷으로 본체 결함을 가리며 통과시키지 않음 |

실제 파일·해시·역할은 `REFERENCE_INDEX.md`와 `references/reference-catalog.json`을 따른다. 최신 파일명만으로 기준을 바꾸지 않는다. 여러 그림 사이의 포즈·비율 차이는 기록하고, 임의로 한 장만 선택해 나머지 시점을 무시하지 않는다.

## 조형 전에 고정할 검토 장면

1. 하나의 동일한 저장 native와 중립 포즈에서 카메라별 비교를 만든다. 원화의 FRONT/SIDE/BACK/3/4와 표정 패널에 대응하는 yaw/pitch/roll을 기록한다. 3/4라는 이름을 무조건45도로 가정하지 않는다.
2. 카메라의 투영 방식, 위치/회전, 초점거리 또는 ortho scale, 해상도, 픽셀 종횡비, lens shift, head/eye pose, 활성 shape key, 프레임을 함께 저장한다.
3. 이미지 정합은 회전·균일 배율·평행 이동만 허용한다. 얼굴 부위별 늘이기, 비균일 배율, 뷰별 메시 변형으로 오차를 숨기지 않는다. 어떤 거리로 정규화했는지 명시하며 그 거리를 검증한 것으로 세지 않는다.
4. 정면의 가로세로·눈·입·턱과 동시에 측면 이마/코/입/턱/후두부 깊이, 사선 눈–광대–볼 전환, 후면 두상/헤어 볼륨을 대조한다. 바디와 의상도 같은 원칙으로 검수한다.
5. 원화의 가림·표정·시점 불확실성은 해당 부위에만 표시한다. 불확실성을 이유로 관찰 가능한 오류까지 보류하거나, 임의 치수를 정답으로 쓰지 않는다.

Shape Key가 있는 메시의 기본 좌표 캐시, Basis 좌표, 활성 키·모디파이어를 거친 evaluated 표면을 혼용하지 않는다. v20에서 캐시/Basis 차이를 얼굴–캡 높이 결손으로 오인한 시도는 실제 렌더에서 회귀가 생겨 폐기했다. 경계 계측은 같은 좌표계와 실제 평가 상태에서 재검증한다.

카메라의 **Clip Start/End**와 뷰포트의 깊이 범위도 별도로 명시한다. v31에서 동일한 눈썹 형상·재질·포즈가 정투영 임시 카메라의 기본 범위0.1..1000m에서 밝은 점으로 깨졌지만, 범위만0.1..10m로 줄인 실제 렌더에서는 사라졌다. 촘촘한 evaluated 표면 검사와 픽셀 방향 광선은 이미 눈썹이 피부 앞에 있음을 확인했다. 이 렌더 오류를 가리기 위해 조형을 부풀리면 안 된다. 현재 약2m 거리의 헤드/4m 전신 검토에는0.1..10m 카메라와 head-centred ORTHO/viewport End10m를 저장·사용하고 실제 값을 기록한다. 다른 크기·거리 장면에는 보이는 대상을 포함하도록 범위를 다시 정하며10m를 보편 규칙으로 강제하지 않는다. 원점·메시 좌표를 옮겨 탐색 문제를 해결하지 않는다. [Blender 공식 깊이 정밀도 설명](https://docs.blender.org/manual/en/latest/editors/3dview/sidebar.html).

## 형상·색·빛을 분리해서 판단

| 검토 모드 | 고정할 것 | 판단할 것 |
|---|---|---|
| 중립 무광/실루엣 | 중립 흰 조명·월드·카메라·포즈·컬러 관리 | 실제 곡면·두께·접합·클리핑·붕괴 |
| UV 검사 | 같은 메시/뷰, 실제 사용 UV | 늘어짐·이음새·텍셀 밀도. 체크무늬 존재만으로 PASS하지 않음 |
| 조명 우회 색 신호 | 활성 재질의 실제 색 경로와 color space | 베이스 컬러/배색/선/메이크업 및 고정된 밝기 패턴. 자동으로 순수 albedo라고 부르지 않음 |
| 반사 프로브 | 고정 중립 rig, 명시된 roughness/IOR | 표면 연속성. 최종 재질 제안과 구분 |
| 목표 툰 룩 | 승인한 색 관리와 조명/가상 광원 규칙 | 원화의 명암·선·표면 표현 |

v18 조사 당시 피부·헤어는 주로 색×노멀 기반 음영을 Emission으로 출력했고, Area light가 해당 음영을 제어하지 않았다. 이를 후속 버전의 현재 상태로 복사하지 않는다. v28 G2L 얼굴의 실제 활성 경로는 Diffuse→ShaderToRGB→ramp×packed pigment→Emission이며 장면 조명에 반응한다. v29 C는 이 경로를 보존하고 얼굴/안검 벽에 독립 cosmetic·shadow/specular/roughness controls와 실제 BSDF 반사 경로를 추가했다. 나머지 헤어/바디까지 같은 방식이라고 추정하지 않는다. 활성 Output ancestry와 actual fixed/moved-light 렌더로 판정하며, 이를 물리적으로 에너지가 보존되는 피부라고 부르지 않는다. 필요한 맵은 목표 셰이더가 결정하며 모든 PBR 맵을 일괄 추가하지 않는다.

검토용 renderer를 재사용할 때는 실제 적용 상태도 확인한다. v003 crease-A에서는 setup 이후 새 재질 복사본을 적용했지만, render 함수가 이전에 캐시한 skin/wall 슬롯을 매 프레임 복원하여 구 재질을 촬영했다. 새 변경을 setup 후 적용했다면 복원 캐시와 실제 슬롯을 함께 갱신하고 촬영 전후 이름/해시를 검증한다. 새 hair/brow actors도 setup에서 수집한 hairOFF 목록에 자동으로 들어간다고 가정하지 않는다. PNG가 저장되고 프로세스가 성공해도 EEVEE shader compile 오류가 있으면 해당 후보 영상은 유효한 아트 검토 증거가 아니다. 정적 pigment를 bake해 shader 부하를 줄일 수 있지만, 속성 숫자만으로 컴파일 성공을 보장하지 않는다.

상체는 흉곽·가슴 돌출부만 따로 맞추지 않는다. 원화의 관찰 가능한 피부 윤곽과 의상 외곽을 구분해 높이별 단면/3D 연결 가이드를 만들고, 흉곽–유방 뿌리–대흉근/겨드랑이–어깨의 연속적인 표면을 함께 본다. 팔 weight의 hard cutoff로 측면 연결을 끊지 않는다. 앞/뒤 겨드랑이 주름은 열린 통로의 양쪽이며 가이드의 bridge 면을 피부 막으로 채우면 안 된다. 명암선·속옷 밑단·내부 관절 pivot을 직접 피부/유방 뿌리 치수로 바꾸지 않는다. 새 imagegen 보조 뷰의 각도·포즈·치수도 프롬프트 값만으로 확정하지 않는다.

엔진별 Material Output도 구분한다. v002 구강 조사에서 MToon 내부의 분홍 Shade Color가 보였으나 실제 EEVEE 출력은 별도의 CompatibleMaterialOutput→Principled 경로였고 Metallic1/Roughness1이었다. 내부 그룹이나 이름·활성 플래그만 보고 실제 치아색 원인으로 단정할 수 없다. 현재 엔진에 대해 API가 선택하는 출력과 실제 연결·UV·알파·면 방향·차폐를 추적하고, 제한된 재질 진단 렌더로 원인을 분리한다. 새 값이나 노드가 존재한다는 사실은 실제 출력에 반영됐다는 증거가 아니다.

## 단계와 통과 조건

1. **참조/검토 장면 준비:** 원화-뷰 대응, 카메라·빛·컬러 관리·측정 정의와 불확실성을 고정한다.
2. **본체 조형:** 얼굴/머리와 바디의 비율·실루엣·깊이·곡면을 대응하는 다각도 원화로 검수한다. 유방·골반·목선은 현재 미해결이다. 얼굴 진행이 바디 승인을 대신하지 않는다.
3. **변형 구조·UV·기초 룩:** 눈꺼풀/눈/눈썹/속눈썹/입의 실제 연결과 최소 blink/smile 테스트, UV/기초 색을 조형과 함께 확인한다. shape key 이름/개수 보존은 정상 표정 증거가 아니다. 필요한 경우 파생 topology/transfer를 하며 원본을 보존한다.
4. **독립 헤어·의상·소품:** 원화의 가닥/부위 의미를 보존하는 소유권으로 구성한다. 단순 공간 그룹이나 자동 loose-part 분리를 최종 파트 구조라고 부르지 않는다. 숨겨진 피부는 원본 보존과 되돌릴 수 있는 가림 전략을 먼저 설계한다.
5. **최종 리깅·보정·모션:** 정적 조형/표면이 승인된 후 진행한다. 중간의 작은 변형 검사는 조형을 위한 진단이다. 의상/헤어 clipping, 허용 pose, 공통 idle, 전환/루프/30fps 재현성은 별도 검증한다.

각 수정은 변경 전과 후를 **동일 검토 조건**으로 비교하고, 관련된 모든 시점에서 새 회귀가 없는지 확인한다. 사용자의 제안은 가설로 검토하고 근거가 없으면 이유를 설명한다. 무조건 수용이나 무조건 반대 대신 실제 근거로 수정 방향을 정한다.

## 재개·압축·위임 시 불변 조건

- `CURRENT_STATE.json`의 선택 native SHA, 기준 원화, 미해결 항목, 금지된 승격을 읽은 다음 작업한다.
- 최근 부분 수정만 요약해서 가슴·골반·얼굴·헤어의 기존 FAIL을 잃지 않는다. 상태는 명시적인 새 증거가 있을 때만 바뀐다.
- 실행/해시/파일/UV/키 보존과 **원화 정합·변형 품질**을 별도 칸에 기록한다. 후자가 미검증이면 PASS가 아니다.
- 생성 원화, 생성 페인트 밑그림, 실제 native 렌더를 구분한다. 실패 후보와 적용하지 않은 제안을 현재 결과처럼 제시하지 않는다.
- 새 입력을 쓰거나 기준을 바꾸면 이유와 영향 범위를 기록한다. 여러 버전 중 최신이라는 이유만으로 승격하지 않는다.
- 변경 담당자와 독립 검토자는 실제 대응 이미지·카메라/빛 설정을 읽고 판단한다. 정합하지 않은 이미지만 보고 비율의 수치를 확정하지 않는다.
- 미완료 결과는 WIP로 보존할 수 있지만, 완료 보고·의상/최종 모션 승격의 근거가 될 수 없다.

이 문서는 압축이 실제 원인이었다는 진단이 아니다. 압축·인계 후에도 누락되면 안 되는 제작 기준을 저장소에 고정한 것이다.

## 중간 산출물과 저장 공간

2026-11-02 사용자의 중간 작업물 정리 요청으로 미채택·미추적 전체 씬과 이전 백업335개를 삭제했다. 명세와 실제 삭제·보호 해시 확인은 `blender/mia-refinement-v002/storage/cleanup-manifest.json` 및 `cleanup-result.json`에 남긴다. 그 명세에 포함된 옛 native 경로는 **과거 실행 기록**이며 현재 파일이 남아 있다고 주장하지 않는다. 원화, 선택된 기준본, 현재 후보, 제한된 핵심 연구본, 코드·부위별 델타·맵·비교 이미지·측정 기록은 보존한다.

새로운 작은 수정마다 수백MB의 전체 씬을 복제하지 않는다. 좌표/키/UV/재질의 범위 제한 델타와 실제 비교 이미지를 우선 보존하고, 전체 native는 기준본·현재 작업본·검토 중 후보에 한정한다. 채택·철회 결정 뒤 중복 후보와 오래된 자동 백업을 해당 단계에서 정리하고 삭제 기록을 남긴다. 큰 실험 native는 지정된 작업 캐시에 저장하며, 캐시 이동만으로 정리를 끝냈다고 보고하지 않는다. 원본·선택본·고유한 수작업을 임의로 제거하거나 Git 이력을 다시 쓰지 않는다.

같은 정리의 후속으로, 당시 보호했던 BodyD가 검증된 G로 대체된 뒤 미채택6개 씬/백업을 추가 정리했다. 총341개49,331,569,802bytes이며 `blender/mia-refinement-v002/storage/cleanup-consolidated.json`이 실제 부재 확인과 현재 보호본 해시를 기록한다. 첫335개 정리 당시의 보호 목록과 현재 선택본을 혼동하지 않는다.

R3b의101프레임 검증 뒤 OP·실패한 R3 전체 씬2개도 같은 절차로 정리했다. 최종 누적343개49,835,048,436bytes다. 원본v001·재현 기준R2·현재R3b와 작은 델타/맵/실제 비교 자료를 유지하며, 삭제한 OP/855d 경로는 과거 기록으로만 읽는다. 한도/드라이버 검증에는 속성의 값·수식뿐 아니라 hard/soft 범위도 포함한다. PresetTotal의 max1이 SUM2를 실제1로 잘랐던 실패를 단일 표정 성공으로 덮지 않는다.
