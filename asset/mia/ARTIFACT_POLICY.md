# Mia 제작 자료의 Git 보관 기준

2026-11-03부터 신규 제작에 적용한다. 커밋은 자주 하되, 실험 산출물 전체를 커밋하지 않는다.

## 무엇을 보관하는가

| 종류 | Git에 보관 | 위치/원칙 |
|---|---|---|
| 원화·표정·바디 기준 | 예 | 기존 `references/`와 역할 인덱스 유지. 생성 후보를 자동으로 승인 기준으로 바꾸지 않는다. |
| 제작 소스 | 예 | Python·설정·재질/리깅 정의·수정 의도·재현 명령. 기존 소스 경로를 계속 쓸 수 있다. |
| 고유한 수작업 | 예 | 신규 `source/` 아래에 원본 페인트·UV·부위 델타 등을 명확히 보관한다. 재생성 가능한 export와 구별한다. |
| 선택한 의미 있는 단계의 모델 | 제한적으로, LFS | 신규 `checkpoints/` 아래에 모델 SHA·선택 범위·실패/미검증과 재현 입력을 기록한다. 매 후보마다 전체 씬을 추가하지 않는다. |
| 핵심 검토 결과 | 선별 | 신규 `reviews/`에 원화 대응 정면/측면/후면/사선 비교, 필요한 상하 시점, 작은 판정 요약과 대표 미리보기를 보관한다. |
| 원시 회전 프레임·실험 메시/atlas·중간 베이크·실패 전체 씬 | 기본 제외 | 로컬 작업 캐시. 현재 단계의 검수와 복구에 필요한 기간은 유지하고, 단계 종료 뒤 재현 가능성과 고유 수작업 보존을 확인해 정리한다. |

신규 `blender/` 연구 폴더의 PNG/GIF/EXR/NPZ/BLEND 등 export는 기본 ignore다. 참조 원화와 앞으로의 `source/`, `checkpoints/`, `reviews/`는 이 규칙의 대상이 아니다. 결과를 Git에 보관할 때는 목적에 맞는 곳으로 선별하고, 단순히 `git add -f`로 모든 실험 결과를 다시 넣지 않는다. Git에 보관하려고 전체 캐시를 다른 경로에 복제하지 않는다.

**Ignored는 삭제 가능하다는 뜻이 아니다.** 고유 수작업·현재 입력·채택본은 보호한다. 수작업을 먼저 source/checkpoint로 보존하고 실제 재개/검수를 확인하기 전에는 임시본을 제거하지 않는다. 자동 삭제나 Git 이력 재작성은 이 정책에 포함하지 않는다.

## 검증과 보관을 구분한다

기존 `REFERENCE_REVIEW_GATE.md`의 원화 대응·카메라/빛/포즈·실제 다각도 렌더·저장본 재열기·독립 판단은 그대로 수행한다. Git 보관량을 줄인다는 이유로 검증을 줄이거나 수치만으로 ART PASS하지 않는다.

전체 원시 프레임은 현재 로컬 검수 패키지에 존재해야 한다. Git의 작은 요약은 원본 파일의 SHA·로컬 위치·대응 checkpoint·재현 명령·검증 범위와 한계를 적는다. 원본을 Git 밖에 뒀으면 Git clone만으로 과거 원시 렌더를 즉시 열 수 있다고 주장하지 않는다. 장기 배포/감사에 전체 패키지가 필요하면 별도 보관 목적지를 먼저 정하며, 이 문서만으로 외부 업로드를 실행하지 않는다.

## 커밋 전 확인

1. 변경 파일 목록을 보고 source/선택본/검토 요약인지 확인한다. 원시 프레임 전체·중복 NPZ·상태 전수 덤프를 일괄 stage하지 않는다.
2. LFS pointer의 작은 크기가 아니라 실제 payload 크기와 새 고유 oid 수를 확인한다. 파일명을 재사용해도 내용이 바뀌면 새 LFS 버전이 쌓일 수 있다.
3. JSON은 필요한 측정 요약과 파일 해시를 보관하고, 매 렌더마다 동일한 장면 전체를 반복 기록하지 않는다.
4. 기존 tracked binary가 수정되면 ignore로 보호되지 않는다. 이전 실험 경로를 계속 덮어쓰기보다 로컬 캐시와 위의 선별 경로를 사용한다.

## 현재 누적량과 이전 자료

기준 HEAD `11f096e`의 Mia tracked 경로는7,614개다. 일반 Git 파일7,504개는 논리 합계2,671,790,213bytes이며, 그중 PNG4,091개가2,110,368,910bytes다. LFS110pointer 경로는104고유 payload/6,875,450,771bytes를 참조한다. 같은 payload의 중복 경로는 LFS 저장량을 중복 합산하지 않는다.

HEAD에서 도달 가능한 Mia 이력은 일반 고유 blob2,573,982,883bytes, LFS107고유 payload/6,922,876,192bytes다. 대부분의 후보가 과거 이력에만 남은 것이 아니라 최신 트리에 계속 포함되어 있다. 이는 논리 내용량이며, 로컬 C/D 캐시 합계를 원격 요금/할당량으로 해석하지 않는다.

이번 변경은 기존 tracked 파일·선택본·Git 이력을 제거하지 않는다. 기존 후보의 추적 해제는 참조/재현 의존성을 분류한 별도 정리다. 추적 해제나 일반 삭제만으로 과거 Git/LFS 저장량이 없어지지 않으며, 이력 재작성/force-push/원격 객체 제거도 이번에 수행하지 않는다.

- [Git 공식 gitignore 문서](https://git-scm.com/docs/gitignore): 이미 추적하는 파일에는 ignore가 적용되지 않는다.
- [GitHub LFS 저장량 설명](https://docs.github.com/en/billing/concepts/product-billing/git-lfs): 변경된 LFS 파일의 새 전체 버전이 저장량에 포함된다.
